# Audit and usage export

Administrators can retrieve bounded pages from `/admin/api/exports/audit` and `/admin/api/exports/usage`. Parameters are timezone-aware ISO8601 `since` (inclusive), `until` (exclusive), and `limit` (1–1,000). Default window: preceding day; maximum: 31 days. Response includes `records`, the fixed window, and optional `next_cursor`. Send the cursor alone with a limit for subsequent pages. Cursors are signed, bind the export kind and administrator identity, and cannot expand the selected window.

Records contain metadata only, using the same redacted representation as administration. No provider credentials, prompt bodies or model output are exported. Pull the pages from your own controlled SIEM/archive tooling; Brrrtgate does not send logs to third parties automatically. Protect export credentials and exported data, which includes user IDs and usage information. Account-root signing-key rotation invalidates outstanding cursors.

Fixed-window keyset pagination is not a long-lived database snapshot. Concurrent transactions that started earlier can commit later, and application clocks can differ. For continuous ingestion, use overlapping windows and deduplicate by record ID, then reconcile against periodic exports/backups. A privileged database administrator can alter database audit records: this feature does not claim immutable or tamper-proof storage. Configure retention, write-once archives and regulatory controls at the destination when required. The endpoint does not delete source records.

Completed local collector windows can be authenticated with an optional [offline audit seal](audit-sealing.md). A dedicated external key and trusted anchor detect changes relative to the sealed snapshot; this is not source-completeness proof, WORM storage or nonrepudiation.
